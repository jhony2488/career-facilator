# 13. Profile Intake (PDF → Master Profile)Module responsible for turning the user's documents (PDF resumes) into the **master profile**, the single source of truth for triage and asset generation. The master profile is a Markdown file editable in any text editor — the user can review, fix and extend it manually.## 13.1. Anti-fabrication rule (invariant)The system **never** creates professional data. Nothing enters the master profile without one of these two origins:1. Content literally present in a document provided by the user;2. A manual edit made by the user in the master file.Fields not found in the document remain empty (`NÃO_INFORMADO`) — they are never inferred from context or the LLM's common sense. This rule is the foundation of the contract already required by resume generation (see `05-geracao-curriculo.feature`): tailoring may only reorder and emphasize what exists in the approved profile.## 13.2. Intake pipelineThe flow is orchestrated by `intakeCore.ts`, which triggers the sequence below both for PDFs detected in the watched folder and for the import command:```text┌─────────────────────────────────────────────────────────────────────────┐│                    0.            ││                       low-confidence excerpts are flagged.              ││                          │                                              ││                          ▼                                              ││  masterProfileStore.ts Writes storage/profile.draft.md (draft).         ││                       Merge or replace chosen at import time:           ││                       • Merge: adds new data; conflicts are flagged     ││                       • Replace: previous version goes to history       ││                          │                                              ││                   [ Mandatory human approval ]                          ││                          │                                              ││                          ▼                                              ││  profileCompiler.ts   Validates the MD and compiles src/config/         ││                       profile.master.json (typed artifact for the       ││                       prompt cache block). Invalidates the cache and    ││                       flags Fit Scores for recalculation.               │└─────────────────────────────────────────────────────────────────────────┘```**Watched folder in practice:** `career-facilitator import --inbox` sweeps `profile_inbox/` and imports each PDF as `INBOX` source; `--watch` keeps continuous monitoring (drop a PDF in the folder and it is processed automatically). Every swept file — readable or not — is archived under `profile_inbox/processed/`, so no document is reprocessed or alerted twice.## 13.3. Human review flowAligned with the global Human-in-the-Loop principle, **no extracted content takes effect automatically**:1. A processed PDF generates/updates `storage/profile.draft.md` — excerpts extracted with low confidence enter **flagged for review**;2. The user reviews the draft (readable diff against the active version);3. On approval, the draft is promoted to `src/config/profile.master.md` and compiled — the previous version becomes a **snapshot** in the history (one per approval);4. While a draft is pending, the system keeps using the last approved version.The user may also edit `profile.master.md` directly — the next run recompiles and adopts the changes.## 13.4. Master profile format (Markdown)`profile.master.md` uses fixed, predictable sections, validated by `profileCompiler.ts`:- **Personal data** — name, contacts, links (LinkedIn, GitHub, portfolio)- **Summary** — professional title and short pitch- **Experience** — role, company, period, responsibilities and metrics- **Projects** — name, stack, measurable outcome- **Open Source Projects** — name, repository, contribution, measurable outcome- **Skills** — stacks, languages, certifications- **Education** — course, institution, period- **Standard answers** — reusable blocks for common free-text questionsThe compiler rejects/partially compiles sections outside the spec, flagging to the user what needs fixing — never "correcting" by fabricating content.## 13.5. Configuration```typescriptprofile: {  inboxDir: 'storage/profile_inbox/',        // Watched folder for new PDFs  draftPath: 'storage/profile.draft.md',     // Draft awaiting approval  masterPath: 'src/config/profile.master.md',// Editable source (active)  compiledPath: 'src/config/profile.master.json', // Prompt cache artifact  historyDir: 'storage/profile_history/',    // Previous versions (replace/rollback)}```## 13.6.
